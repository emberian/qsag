Volatile coupon continuation — astra-vcoupon-v2-full
2026-11-15 — Codex

IMPLEMENTED

The existing authenticated binary-SPDZ WOTS+C sweep now has an output sink.
PendingCouponBatch samples fresh private OS entropy, evaluates only the chosen
fixed subset, writes retained shares directly into LockedBytes, and independently
rerandomizes every retained coordinate before certification. Two disjoint
64-chain sessions run concurrently with distinct session IDs and private RNGs.
Both must finish their authenticated endpoint openings before certification.

ProtectedMintProcess locks current/future mappings and disables process dumps.
It must be enabled in a dedicated worker before its secret inputs are created or
loaded. This process-wide protection is intentionally permanent. Final coupon
mappings additionally retain DONTDUMP, WIPEONFORK, PID checks and volatile erasure.
Forking a mint worker with secret scratch is unsupported. This does not protect
against privileged memory reads, RAM snapshots, hibernation or restored entropy.

AuthenticatedWaistband MACs the actual Baggy cache and its volatile consistency
records. It starts empty, precomputes covered roots from MPC, checks its MAC before
each release, and poisons itself on signing failure. Its state and MAC key are not
serialized. The existing Baggy lifetime signature budget still applies across
restarts.

PendingCouponBatch can certify descriptors through the actual Baggy MPC signer
and install the locked tables into CouponPools. Online opening/combining never
calls a WAL. The root certificate is an ordinary BaggySig. The resulting online
signature is a certificate-plus-WOTS+C envelope checked by volatile_coupon::verify.

Compact1122Bundle uses the real qsag-fts signer/verifier, binds full public keys,
bundle size, root, index and child payload, rejects duplicate keys, and consumes a
different OTS key for each child. Fan-out verification rejects duplicate indices
and keys. These are existing durable FTS keys: their WAL is still mandatory.
The helper does not bypass FTS persistence or claim that regenerating seeds is safe.

Clippy's two triple_f2 type-complexity warnings are replaced by a shared outcome
alias. Additional existing quorum test/transport and DKG-test warnings encountered
by the requested command were corrected without changing their protocol behavior.

OUTSTANDING — THE FULL V2 DELIVERABLE IS NOT COMPLETE

1. No concrete PORS+FP implementation has been added. Root certificates still use
   Baggy's existing FORS+C and 128-chain WOTS+C suite. PORS+FP needs its actual
   index selection, forced-pruning bound, canonical multiproof representation,
   authenticated MPC openings, parameters/security accounting and root integration.
   A renamed FORS certificate would not establish this property.

2. Baggy's root MPC is still the 2-of-3 Rss256Engine. Arbitrary all-of-subset coupon
   shares do not raise the parent root's threshold. The existing arbitrary-t
   SpdzSlhMpcCluster in qsag-core/keccak_mpc.rs is a possible basis for a Baggy
   adapter, but presently exposes FIPS-205 oracles, not Baggy/PORS+FP sweeps.
   HemSpdzSeedQuorum is stateful Poseidon2 Jorts and is not a stateless substitute.

3. The online envelope is not a raw BaggySig or QuorumJortsSig over the user's
   message. Direct v2 wire compatibility and downstream verifier integration
   remain to be implemented. Consumers must call volatile_coupon::verify today.

4. Dealerless staging remains an in-process orchestration of participant states,
   as in the existing staging backend. It is not separate-host process isolation.

5. The root Cargo.lock is outside this lane's owned paths and was not edited.
   Its qsag-quorum package entry needs qsag-accel (test backend) and qsag-fts
   (production Compact1122) dependencies. Cargo generated the corresponding
   updated lockfile in the authorized remote validation directory.
