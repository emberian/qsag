# Credential/CLI rake status

Updated 2026-11-15 by Codex (`astra-rake-cred-cli`). **Partial: the requested Shamir protocol replacements are not implemented.**

Implemented in this lane: indexed accumulator replay checks and incremental Merkle updates; 32-attribute issuance/disclosure; ML-DSA-44/65/87 transport authentication; bounded 16-party RSS and SIMD binary-field dot products; batched TOPRF and ML-DSA XOF extraction; encrypted per-party TOPRF share codecs and CLI reload without DKG; indexed, verified aggregation authorship; HD count 65,536, policy parties/tiers 64, quorum height 20; Compact1122 and accurate Full256Bit aliases. FTS enrollment/signing use the underlying u16 party limit; aggregation enrollment uses the existing key-file byte budget instead of 64 validators.

Compatibility: selective-disclosure encoding is now `QSAG.BVC.SD.LIMBO256.V2` (192-by-192 multiplication grid), retaining N=256, GF(p^5), and 17/33 repetitions. V1 presentations are rejected; generate fresh presentations from existing small credentials. Small-credential commitments remain unchanged. `fts-frontier-1058` remains an alias for `fts-frontier-2338`, never Compact1122. Automatic aggregation requires authenticated-by-verification `validator_public_key` metadata; raw/legacy signatures require `--signers`. TOPRF envelopes retain `cshake256-iterated-v1`; legacy seed vaults retain their explicit compatibility path.

Outstanding protocol work:
- TOPRF is still the actively checked five-server replicated circuit with privacy threshold two. `Config::new` still rejects other committees. Its four start votes and four-holder input checks are unchanged. Persisted bundles eliminate enrollment replay but **do not** allow deletion of three parties and evaluation from two files. Supporting arbitrary `2 <= t <= n <= 64` and exactly `t` online servers needs a different nonlinear MPC protocol; ordinary Shamir/BGW multiplication alone does not provide dishonest-majority availability. No absent party is simulated and no master key is reconstructed.
- ML-DSA's identifier ceiling is 64, but its only backend is RSS, explicitly bounded at 16; larger enrollments now fail before network rounds. A polynomial-sharing backend, including arithmetic/binary conversion and malicious multiplication checks, is still required for arbitrary 64-party committees. Signing still needs `2t-1` online custodians.
- The earlier RSS/Jorts active-subset, HEM subset-aware durable latch/policy, production hypertree, threshold migration-prover, and live policy-state migration dependencies were not resolved by this lane. Volatile-Coupon CLI wiring also remains outside this implementation. The status file must not be removed on the claim that only Volatile-Coupon remains.
- Transport is still in-process. The legacy envelope's per-chunk keystream framing and Unix entropy source remain; silently changing the cipher under the same envelope version would break existing files. The stale universal `--seed-file` entropy error hint was removed (keygen itself already supports that flag).
