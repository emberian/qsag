# QSAG assurance and deployment boundary

**qsag — Quorum-Switching AGgregation / Quantum Succinct AGgregation** combines standardized signature formats with custom Pants threshold/aggregation protocols. This document separates machine-checked statements about named artifacts from the integration obligations required to apply them to deployed requests. The stack remains a research preview.

## Signature equivalence is a matched-input claim

For **FIPS 205 SLH-DSA-SHAKE, Baggy, Jorts 2-of-3, and QS-B (`BftShamirJorts`)**, the intended and modeled equality is pointwise: successfully evaluated threshold bytes equal the canonical single-signer bytes for the **same key, parameters, leaf/message and hedging seed/randomizer**. Under that coupling the emitted bytes have statistical distance **0**. FIPS 205 has explicit matching-key/message/randomizer model theorems; production refinement, grinding/caching equivalence and scheduler laws must be checked per path. A byte-equality result does not prove that separate entropy policies have the same law, nor that successful outputs conditioned on malicious abort are distributed like unfiltered standalone outputs.

FIPS 205 and threshold **FIPS 204 ML-DSA-44** are standard-verifier compatible. ML-DSA compatibility alone is not a perfect-distribution theorem. Custom Pants signature formats are not NIST formats.

**QS-A (`CommitteePartitionedJorts`) is committee-revealing partitioned custody.** Its leaf is `committee * leaves_per_committee + epoch`; disjoint ranges identify the committee under the public layout. Distinct committees have disjoint signature support. A standalone signer using the same committee-specific schedule can match bytes, but that does not hide the committee. QS-A permits t-of-t online signing when $2f>t$, with safety **and abort**, not guaranteed completion against withholding signers.

**QS-B** uses a single global tree and quorum-independent leaf allocation. Certified BeltLatch requires $2q>n+f$; the BFT availability regime requires $n\ge3f+1$. The signing threshold $t$ need not equal the latch quorum $q$. Its self-verifying Shamir WOTS+C shares are MAC-free; latch certification still needs authentication. Neither mode promises transport anonymity.

## Cryptographic profiles and assumptions

- **Baggy / Waistband:** stateless hypertree/TSW and static Top-$L$ internal child-root signatures; never pre-message pools of message-binding leaves. Full 256-bit WOTS+C uses `w=4, chains=128, target_sum=192`. No stateful signing-leaf exhaustion is required, but finite query budgets, hash/PRF assumptions, cache binding and first-success grinding still matter. Stateful preprocessing, nonce and session resources are separate from stateless signing.
- **Jorts:** one-time leaf use, crash-WAL and BeltLatch are essential. A RAM latch is not durable custody. Cached/retried signatures must preserve the authorized message, leaf and retry law.
- **Hem:** GoldilocksExt4 is $\mathbb{F}_p[v]/(v^4-7)$, $p=2^{64}-2^{32}+1$, $p^4>2^{255.99}$. WHIR uses `Habr24Qrom128` by default, $q=(128,64,43,32)$, or `BciksJohnsonQrom128`, $q=(257,129,87,65)$. The former uses conjectural agreement; the latter uses unconditional Johnson coding bounds with slack. The aggregate verifier enforces a mandatory 128-bit QROM Grover query-search floor and compatible merge profiles. This is **query accounting**, not total quantum security: field/folding/OOD errors, list sizes, commitment binding, all stages/sessions and a concrete multi-round Fiat–Shamir reduction remain necessary. “Unconditional” does not apply to the entire cryptographic protocol. Merge trees check constituent proofs and disjoint signer sets, not recursive SNARKs.
- **RLWE preprocessing:** the actual challenge is a signed-monomial ring element. A Boolean-challenge extractor does not establish extraction for a polynomial difference; invertibility/exceptional cases, witness norms and FS/QROM losses must be proved for the real relation. Increasing joint challenge width addresses generic search only. It is not a full quantum-active OT theorem.
- **Threshold ML-DSA-44:** active signing uses $2t-1$ custodians, an honest majority among online signers. Only ML-DSA-44 is enabled. Rejected attempts keep `z` closed but expose `(w1, reject)`; transcript privacy relies on the threshold Fiat–Shamir-with-aborts heuristic. Attempt limits, nonce burns and selective delivery are part of the output law.
- **TOPRF / BlindVC:** 2-of-5 Poseidon2 TOPRF uses replica correction for one malicious server. BlindVC has six-limb commitments and a 438-repetition `Quantum128` profile. The profile still relies on commitment and FS assumptions; it is not a universal security certificate.
- **HD / FTS / policy:** secret-keyed dealerless HD setup assumes authenticated confidential channels and honest-majority ceremonies; watch-only batch enrollment can reconstruct selected child seeds. FTS use limits and burns are mandatory. Rolling-window BDOZ authorization requires an authoritative clock or agreed logical epochs, not arbitrary caller timestamps.
- **Migration:** three-party co-ZK for secp256k1/Taproot/Ed25519 now has mandatory active pre-open multiplication checks and cross-batch barriers. Conditional privacy and active-check guarantees must be tied to actual transcripts. Two colluding custodians are outside the one-corruption privacy model. The current ZKBoo default is 219 repetitions; this classical margin is not a 128-bit QROM claim. The stronger profile and complete reduction remain integration work.

## Storage, transport and release composition

`PosixCrashWal.lean` models volatile kernel state, writeback/NVMe persistence, torn writes, file and parent-directory synchronization, genesis seals and recovery. `flock(2)` ownership is by **OpenDescriptionId**, not PID: independent opens in the same process contend; duplicated/inherited descriptors share a lock and do not provide thread mutual exclusion. The runtime still needs its per-handle synchronization and the host's promised persistence semantics.

Correct atomic replacement of one record does not prove atomicity across policy spend, leaf reservations, preprocessing cursors, nonce burns and poison state. Every useful partial output needs prior durable reservations in the same bound ceremony context. One journal or a sound monotone burn-only multi-ledger protocol must establish this under crashes and interleavings. Forgetting an affine Rust permit must burn availability, never recycle a resource. Disk/VM snapshot cloning requires an external monotone anchor or explicit exclusion; filesystem WALs alone cannot prevent it.

Loopback/RAM and simulated WAN measurements do not measure a durable authenticated deployment. Required channels provide **confidentiality and authenticity**, session/peer/round binding, replay protection across reconnects and consistent broadcast where used. A MAC-sealed framed TCP message is not encrypted. Local aggregate engines holding all shares do not establish separated custodian security.

Complete mediation requires secret ownership and bound release objects inside the checked boundary, with private resource leases, context binding, poison checks, and durable receipts. An optional verified guard beside raw share access does not supply that property. Sequential session proofs must be extended or instantiated for the real concurrent scheduler and shared authority.

## Hardware and trusted computing base

ISA observations cover specified PC, memory-address and variable-latency events under x86_64 DOIT and aarch64 **PSTATE.DIT** assumptions. Capability enumeration is not proof that the operating mode is enabled. Scratch zero-on-exit covers named registers and frame locations; preserved caller registers, compiler copies, old allocations, OS context saves, speculation, SMT effects and physical faults require separate treatment. `vzeroupper` is not full vector erasure; a call is not a scrub operation.

The TCB includes human theorem-statement review, Rust/MIR generation, Charon/Aeneas and their prelude semantics, higher-level rustc/LLVM code generation, assembler/linker and artifact selection, CPU semantics, OS entropy, durable storage and host isolation, transport provisioning, and policy time authority. Independent proof-kernel replay reduces checker dependence but does not validate a wrong theorem statement or stale extraction.

## Verify your code, test your specs

The acceptance chain is: production entrypoint → exact source/configuration → fresh extracted body → theorem with inhabited premises and explicit assumptions → concrete security profile → linked symbols/dispatch closure → artifact digest → positive/negative tests. `KatGen`, spec-oracle differential tests, clause-drop witnesses, native ISA cosimulation and dudect supply complementary evidence. Missing hardware or an unexecuted gate must remain unverified, not be recorded as passed.
