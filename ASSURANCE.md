# QSAG assurance and deployment boundary

The recorded 2026-11-14 compiled-kernel freshness gate passed: fresh Rust 1.99.1 release archives matched all **19 x86-64 and 9 AArch64 certified assembly kernels**, with zero changed, missing or unpinned kernels. The corresponding Lean certificate checks pass. This covers the named kernel bytes and their explicit ISA contracts; complete linked-program certification remains separate.

**Recorded runs, not the working tree.** The axiom audits, kernel replays and freshness gates cited in this document are runs recorded against a specific source state. The Lean library has since been reorganised into the domain directories described in the [proof architecture guide](docs/PROOF_ARCHITECTURE.md), so declaration and module counts from earlier runs describe those earlier bytes; they are neither a check of the present tree nor a statement of production refinement. A claim about the present tree needs a fresh run of the four gates: `lake build --wfail` with the `audit-axioms` executable in `lean/`, the MIR audits under `aeneas/lean` and `aeneas/lean-whir`, `python3 scripts/check_extraction_provenance.py`, and `python3 scripts/check_lean_policy.py`.

**qsag — Quorum-Switching AGgregation / Quantum Succinct AGgregation** combines standardized signature formats with custom Pants threshold/aggregation protocols. This document separates machine-checked statements about named artifacts from the integration obligations required to apply them to deployed requests. The stack remains a research preview.

## Signature equivalence is a matched-input claim

For **FIPS 205 SLH-DSA-SHAKE, Baggy, Jorts 2-of-3, and QS-B (`BftShamirJorts`)**, the intended and modeled equality is pointwise: successfully evaluated threshold bytes equal the canonical single-signer bytes for the **same key, parameters, leaf/message and hedging seed/randomizer**. Under that coupling the emitted bytes have statistical distance **0**. FIPS 205 has explicit matching-key/message/randomizer model theorems; production refinement, grinding/caching equivalence and scheduler laws must be checked per path. A byte-equality result does not prove that separate entropy policies have the same law, nor that successful outputs conditioned on malicious abort are distributed like unfiltered standalone outputs.

FIPS 205 and threshold **FIPS 204 ML-DSA-44/65/87** are standard-verifier compatible. ML-DSA compatibility alone is not a perfect-distribution theorem. Custom Pants signature formats are not NIST formats.

**QS-A (`CommitteePartitionedJorts`) is committee-revealing partitioned custody.** Its leaf is `committee * leaves_per_committee + epoch`; disjoint ranges identify the committee under the public layout. Distinct committees have disjoint signature support. A standalone signer using the same committee-specific schedule can match bytes, but that does not hide the committee. QS-A permits t-of-t online signing when $2f>t$, with safety **and abort**, not guaranteed completion against withholding signers.

**QS-B** uses a single global tree and quorum-independent leaf allocation. Certified BeltLatch requires $2q>n+f$; the BFT availability regime requires $q\le n-f$ (jointly feasible when $n\ge3f+1$). The signing threshold $t$ need not equal the latch quorum $q$. Its self-verifying Shamir WOTS+C shares are MAC-free; latch certification still needs authentication. Neither mode promises transport anonymity.

## Cryptographic profiles and assumptions

- **Baggy / Waistband:** stateless hypertree/TSW and static Top-$L$ internal child-root signatures; never pre-message pools of message-binding leaves. 256-bit digest WOTS+C uses `w=4, chains=128, target_sum=192`. No stateful signing-leaf exhaustion is required, but finite query budgets, hash/PRF assumptions, cache binding and first-success grinding still matter. Stateful preprocessing, nonce and session resources are separate from stateless signing.
- **Jorts:** one-time leaf use, crash-WAL and BeltLatch are essential. A RAM latch is not durable custody. Cached/retried signatures must preserve the authorized message, leaf and retry law.
- **Hem:** GoldilocksExt4 is $\mathbb{F}_p[v]/(v^4-7)$, $p=2^{64}-2^{32}+1$, $p^4>2^{255.99}$. WHIR defaults to `BciksJohnsonQrom128` (wire tag 4), $q=(258,130,88,66)$ with 16-bit proof of work, the only regime whose nominal per-round Grover search work, 136 bits, clears 128 bits with no bound on the number of oracle queries (`meets_unconditional_grover_128_floor`). Aggregate authorization (`meets_qrom_128_floor`, a historical name) also accepts four bounded-query [CDHZ25] profiles, tags 5–8, whose nominal Grover round work is 108 bits (tags 5 and 7, accounted for at most $2^{38}$ oracle queries) or 107 bits (tags 6 and 8, $Q+1\le2^{40}$); these do not meet a 128-bit Grover floor and promise nothing at $2^{64}$ queries. The classical Johnson regime (tag 2, 72 bits) is available only to lower-level PCS callers and is never authorized for aggregates. Capacity-proximity wire tags 0, 1 and 3, including Habr24, are retired and rejected. Merged proofs must carry compatible profiles. The [regime table](docs/SECURITY_AND_CT_PROOFS.md#hem-profile-and-qrom-accounting) gives the figures per regime. The Johnson query bound does not discharge the CWYZ `NonExcludedDecompBound` or concrete multistage acceptance reduction. All of this is **query accounting**, not total quantum security: field/folding/OOD errors, list sizes, commitment binding, all stages/sessions and a concrete multi-round Fiat–Shamir reduction remain necessary. “Unconditional” does not apply to the entire cryptographic protocol. Merge trees check constituent proofs and disjoint signer sets. Compact hierarchy authorization requires `VerifiedHierarchicalHemEvidence` from full child verification; the compact proof itself establishes a public commitment chain, not recursive child verification. The fixed-path child-WHIR merge (`zk_hem/recursive_whir.rs`) certifies up to 16 child PCS openings bound to shard headers inside one parent proof; it does not verify the shard signatures or quorum authorization, and the composed QROM reduction for its transcript is not mechanized.
- **RLWE preprocessing:** 24 jointly hashed challenges in `{±X^k : 0≤k<1024}` give 264 bits, with nominal generic Grover exponent 132. `Protocol/Threshold/RlweCyclotomicExtraction.lean` proves pairwise difference invertibility for odd moduli and power-of-two degree, and short relaxed-witness extraction. The live joint sampler uses Q192 Bernoulli arithmetic and `M = exp(3615102/980000) ≈ 40`. Prover and verifier enforce, per branch and repetition, both the coefficient bound $\lVert z\rVert_\infty \le 3070$ and the Euclidean bound $\lVert z_s\rVert_2^2+\lVert z_e\rVert_2^2 \le 1{,}500{,}000{,}000$ (`RLWE_ZKPOK_PAIR_L2_SQ_BOUND`), which excludes the public solution $s=1$, $e=\mathrm{centered}(-A)$ that an $\ell_\infty$-only check admits. `RlweExtractionBoundary.lean` proves both halves: the $\ell_\infty$ short-SIS branch contains that public solution (`rlweUnitSis_norm_le_6142`), and forked extraction under the Euclidean check lands in a joint relation with $\lVert s\rVert_2^2+\lVert e\rVert_2^2\le6{,}060{,}827{,}392$ that rejects it (`extract_rlwe_or_sigma_24_euclidean_sis_dichotomy`, `tooth_rlweUnitSis_refuted_by_euclidean_bound`). Its finite-precision error and normalized vector-Gaussian/tail premises still need production instantiation; sampler comments alone do not establish them. Quantum-active OT and concrete FS reductions are separate obligations; see the [exact theorem map](docs/SECURITY_AND_CT_PROOFS.md#current-parameter-and-theorem-map).
- **Threshold ML-DSA-44/65/87:** committees have $n\le64$ custodians with $n\ge2t-1$; active signing uses a quorum of $2t-1\le16$ custodians, an honest majority among online signers, who convert Shamir shares into the replicated sharing of the signing engine under multiplication and conversion checks. All three parameter sets are enabled in Rust; the sealed trace simulation still specializes to ML-DSA-44 and takes the trace outcomes as input. Rejected attempts keep `z` closed but expose `(w1, reject)`; transcript privacy relies on the threshold Fiat–Shamir-with-aborts heuristic. Attempt limits, nonce burns and selective delivery are part of the output law.
- **TOPRF / BlindVC:** the 2-of-5 Poseidon2 TOPRF uses replica correction for one malicious server; a Shamir-SPDZ backend covers $2\le t\le n\le64$ with exactly $t$ servers online. BlindVC has six-limb commitments. Under the `Quantum128` profile, blind issuance is a 438-repetition three-party ZKBoo proof, and a selective-disclosure presentation is a 33-repetition, 256-party seed-tree MPC-in-the-head polynomial-multiplication check over $\mathrm{GF}(p^5)$ (soundness $256^{-33}=2^{-264}$ classically, nominal Grover exponent 132; about 9.2 MiB). The same presentation statement is also provable as a committed zk-Hem relation, 239,507 bytes under the bounded-query Poseidon2 profile (tag 7). These profiles rely on commitment and Fiat–Shamir assumptions, and no quantum Fiat–Shamir theorem is claimed for the presentation; none is a universal security certificate.
- **HD / FTS / policy:** secret-keyed dealerless HD setup assumes authenticated confidential channels and honest-majority ceremonies; watch-only batch enrollment can reconstruct selected child seeds. FTS use limits and burns are mandatory. Rolling-window BDOZ authorization requires an authoritative clock or agreed logical epochs, not arbitrary caller timestamps.
- **Migration:** three-party co-ZK for secp256k1/Taproot/Ed25519 now has mandatory active pre-open multiplication checks and cross-batch barriers; standalone 438-repetition ZKBoo ownership modules also cover Pallas (Orchard/RedPallas) and BLS12-381 (G1). Conditional privacy and active-check guarantees must be tied to actual transcripts. Two colluding custodians are outside the one-corruption privacy model. The current ZKBoo default is 438 repetitions, with interactive error `(2/3)^438 < 2^-256` and nominal generic-search exponent 128.1068. Per flush, active Boolean `AND` checks have error `<(63/(2^128-1))^2<2^-244`, large-prime active checks have error `<=35/(p-1)<2^-249`, and cubic-Goldilocks checks have error `<=35/(p^3-1)<2^-186`. Those field-check numbers are distinct prime-domain bounds, not classical/Grover versions of one bound. Complete FS/QROM extraction remains separate.

## Storage, transport and release composition

`Exec/PosixCrashWal.lean` models volatile kernel state, writeback/NVMe persistence, torn writes, file and parent-directory synchronization, genesis seals and recovery. `flock(2)` ownership is by **OpenDescriptionId**, not PID: independent opens in the same process contend; duplicated/inherited descriptors share a lock and do not provide thread mutual exclusion. The runtime still needs its per-handle synchronization and the host's promised persistence semantics.

Correct atomic replacement of one record does not prove atomicity across policy spend, leaf reservations, preprocessing cursors, nonce burns and poison state. Every useful partial output needs prior durable reservations in the same bound ceremony context. `CeremonyAtomicityAndAbort.lean` proves multi-ledger crash/interleaving safety for valid modeled transitions; each production reservation/release path must refine those transitions. Forgetting an affine Rust permit must burn availability, never recycle a resource. Disk/VM snapshot cloning requires an external monotone anchor or explicit exclusion; filesystem WALs alone cannot prevent it.

Loopback/RAM and simulated WAN measurements do not measure a durable authenticated deployment. Required channels provide **confidentiality and authenticity**, session/peer/round binding, replay protection across reconnects and consistent broadcast where used. A MAC-sealed framed TCP message is not encrypted. Local aggregate engines holding all shares do not establish separated custodian security.

Complete mediation requires secret ownership and bound release objects inside the checked boundary, with private resource leases, context binding, poison checks, and durable receipts. An optional verified guard beside raw share access does not supply that property. Multi-turn mediated guard and reachability theorems cover named guards; instantiate the ceremony event model for the real concurrent scheduler and shared authority.

The modeled pre-open selective-abort theorem in `CeremonyAtomicityAndAbort.lean` proves statistical-distance numerator zero under its masked-view protocol specification and positive survival count. It covers that conditioning law; arbitrary post-output withholding has a different output law.

## Hardware and trusted computing base

`SydTvTranslationValidation.lean` supplies five looping-kernel refinement certificates; `SimdBinaryEquiv.lean` covers decoded carryless multiply and transpose fixtures. The current certified ELF inventory is 28 symbols / 3,355 decoded instructions (1,935 x86-64, 1,420 AArch64); the 23-symbol historical generation is retained separately. `SpirvSimtGpuEquiv.lean` proves codec roundtrip, race-conditioned multi-wave confluence and modeled SIMT leakage properties. Exact runtime SPIR-V 1.5 shader words still need a functional bridge to that modeled subset; driver telemetry and keyed receipts are distinct evidence.

ISA observations cover specified PC, memory-address and variable-latency events under x86_64 DOIT and aarch64 **PSTATE.DIT** assumptions. Capability enumeration is not proof that the operating mode is enabled. Scratch zero-on-exit covers named registers and frame locations; preserved caller registers, compiler copies, old allocations, OS context saves, speculation, SMT effects and physical faults require separate treatment. `vzeroupper` is not full vector erasure; a call is not a scrub operation.

The TCB includes human theorem-statement review, Rust/MIR generation, Charon/Aeneas and their prelude semantics, higher-level rustc/LLVM code generation, assembler/linker and artifact selection, CPU semantics, OS entropy, durable storage and host isolation, transport provisioning, and policy time authority. Independent proof-kernel replay reduces checker dependence but does not validate a wrong theorem statement or stale extraction.

## Verify your code, test your specs

The acceptance chain is: production entrypoint → exact source/configuration → fresh extracted body → theorem with inhabited premises and explicit assumptions → concrete security profile → linked symbols/dispatch closure → artifact digest → positive/negative tests. `qsag-kat` (`lean/Main.lean`), spec-oracle differential tests, clause-drop witnesses, native ISA cosimulation and dudect supply complementary evidence. Missing hardware or an unexecuted gate must remain unverified, not be recorded as passed.

## Further model and integration boundaries

The four-layer bridge is a hand-written model-to-model simulation. Its inhabited signer closes over three Shamir shares and returns a keyed tag; it does not instantiate separated custody. Its safety predicate covers spend, nonce uniqueness, epochs and honest quorum membership, not MAC validity or signature authenticity. Round-1 commitments are session-bound; Round-2 offsets are reused in this model, so replay resistance remains an open repair. Bridge witnesses, ELF functional-equivalence additions and custody welds are axiom-audited but are outside the configured challenge rosters. The public witness exposes existence; its unexposed concrete constants are not a downstream reduction API.

The ML-DSA production call treats its extracted gate as an ordering assertion around an unextracted acceptance verdict; it does not supply independent extracted proofs of each norm/commitment check. The policy call uses its extracted guard for checked accumulation, while persistent nonce/window authority remains in unextracted code. These calls do not close complete mediation. Dense PCG remains a standalone correlation path, and ceremony context fields still need live caller integration.

The project-written Aeneas compatibility preludes are separate trusted semantic models, not the upstream Aeneas library. They currently differ between workspaces. The trait-dictionary elaborator and implicit enum discriminants require their own extraction checks. Runtime censuses cover named library owners; executable roots and challenge helper modules are outside those owner counts. The 12 ignored Rust tests include production-depth PCG, production RLWE bootstrap and full-height threshold FIPS soaks; the standard workspace pass does not execute them.

Migration's Boolean active check has a per-flush bound below 2^-127.99, weaker than its field checks. `co_zk_mpc` samples canonical field tapes by rejection (`word < p`), with zero modulo-reduction bias. Exhausting the bounded retries causes an independent liveness abort; no measured full-ceremony abort probability is claimed here.

The filesystem poison/session journal now requires an external monotone anchor in production. It binds the record count and authenticated head, rejects truncated prefixes, and recovers at most one durable unacknowledged append by advancing the anchor. A deployment must provide an anchor outside the journal's rollback domain; the repository supplies test doubles, not a TPM or remote-service implementation. The unanchored constructor is test-only. File-backed benchmark fixtures omit that external service and do not measure its latency.

GPU staging cleanup waits for demonstrated completion before wiping, including failed jobs. A device-lost job may retain staging and device memory because safe completion cannot be established; the engine refuses further work. Other secret-bearing slots require the audited constructor, while BDOZ enforces audit evidence on every backend. CPU fallback counts are observable. SPIR-V receipts use the actual 1.5 header label and a new domain; old receipts are invalidated.
