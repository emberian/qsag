# QSAG assurance and deployment boundary

QSAG combines SLH-DSA and ML-DSA signing, threshold custody, pure-quintic Hem proofs and classical-to-post-quantum key migration. It is a research prototype with no external audit. The evidence below identifies the formal statements, implementation artifacts and deployment assumptions behind each claim.

## Cryptographic profiles and protocol boundaries

### 1. Public aggregation, zero knowledge and recursive IVC

The extension is $\mathbb F_{p^5}=\mathbb F_p[X]/(X^5-3)$ for $p=2^{64}-2^{32}+1$, with cardinality greater than $2^{319.99}$. Frobenius acts by $X^p=\zeta_5 X$, where $3^{(p-1)/5}\bmod p=\zeta_5=1{,}041{,}288{,}259{,}238{,}279{,}555$. [Field implementation](crates/qsag-agg/src/zk_hem/v2/field5.rs)

- **Public committees.** `prove_hem_quintic_128` and `verify_hem_quintic_128` implement `HemQuintic128` (`QSAGHQM2`). The four-key, three-active vector is 360,391 B with `HemQuinticProfile::TurboShake400` (400-bit Canopy) and 381,661 B with `HemQuinticProfile::Poseidon2Gl24` (448-bit, seven-limb Canopy). Inactive padding pins all 138 non-S-box columns to canonical zero. Stage 0 takes 267 queries at $2^{16}$ through $2^{23}$ cells and 266 at $2^{24}$ through $2^{28}$. For both profiles `publicHemQuintic_qrom_soundness_128` bounds the modeled QROM error below $2^{-128}$ for all 13 schedules through $Q\le 2^{64}$. [Public certificate](lean/Qsag/Protocol/Aggregation/PublicHemQuintic128.lean) · [Row constraints](crates/qsag-agg/src/hem_quintic/rows.rs)
- **Regional aggregation.** `HierarchicalHemAggregate` (`QSAGHEM\x04`) includes the public proofs for its regional shards. `prove_hierarchical_hem_prepared` and `verify_hierarchical_hem_prepared` bind them to an independently prepared `PreparedPolicyRegistry`. [Registry and verifier](crates/qsag-agg/src/recursive.rs)
- **Zero knowledge.** zk-Hem v2 uses `QSAGZKH2` locally and `QSAGZKS2` for additive shares. Both wire decoders accept cSHAKE256 (16) and TurboSHAKE256 (17). Stage 0 commits a packed assignment and a folded-domain mask word, with five out-of-domain masking points, a 32-byte per-tree `tree_nonce` and 32-byte per-leaf salts. Optional `LookupV2Proof` adds a jointly masked LogUp helper over `Fp5`. The [CWYZ26] affine folds and [DKT26] Theorem 5.12 line-folding analysis underlie `zkHemV2_packed_all13_qrom_lt_128_at_2pow64` for all 13 deployed sizes. [Wire profile decoder](crates/qsag-agg/src/zk_hem/v2/params.rs) · [Packed-fiber certificate](lean/Qsag/Protocol/Aggregation/ZkHemV2PackedFiberCerts.lean)
- **Binary recursive IVC.** `prove_ivc_tree` and `verify_ivc_tree` implement `SuccinctIvcProof` (`QSAGIVC1`, strict tag `0x00`). `IvcTreeStepRelation` checks both `FixedPathWhirW24` (`QSAGIW24`) child openings over Poseidon2-GL-w24 and `Fp5`. A degree-two sumcheck reduces public-matrix claims to one at the root. The native two-child census is 315,150 rows including closing padding, within $2^{19}$. The full [DKT26] step uses 7,652,354 rows before closing and fits within $2^{23}$. Root size is 639,673 B independent of depth (`ivcRootProof_byteSize_independent_of_depth`). The constructive WHIR and R1CS step checks support straight-line tree extraction. `multidepth_recursive_qrom_lt_2_neg_128` bounds modeled error below $2^{-128}$ up to depth 16 (65,536 shards) at $Q\le 2^{64}$, with zero $2^d$ rewinding loss. That numerical theorem uses the $2^{20}$-cell recursive margin schedule (304, 148 and 100 queries). The serialized Rust root uses `IvcStepConfig::dkt26(23)`. Transferring the depth-16 bound to that schedule requires separate composition. [Binary IVC](crates/qsag-agg/src/zk_hem/recursive_ivc/) · [Tree extraction](lean/Qsag/Protocol/Aggregation/MultiDepthRecursiveQromExtractor.lean)
